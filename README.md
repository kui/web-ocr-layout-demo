# web-ocr-layout-demo

画像を投入すると、ブラウザの中だけでレイアウト認識と OCR を実行するデモページです。検出した領域にマウスを乗せると、その領域の文字を表示します。画像はどこにも送信しません。

- レイアウト認識: PP-DocLayoutV3
- OCR: PP-OCRv6 small（日本語、英語、中国語に対応）
- 推論: onnxruntime-web。WebGPU と WASM を画面で切り替えられます。
- 翻訳: PLaMo 3 Translate 0.8B。読み取った文字を日本語に翻訳します。

## 必要なもの

- Node.js と npm。Node.js は 24 系の 24.11 以降、または 22 系の 22.18 以降です。23 系は使えません。
- WebGPU を使う場合は、WebGPU に対応したブラウザ（Chrome、Edge など）。対応していないブラウザでは WASM だけを選べます。
- huggingface.co への接続。ブラウザが、各モデルを最初に使うときにダウンロードして保存します（合計 約 160 MB）。翻訳を使うときは、翻訳モデル（約 570 MB）も最初の 1 回だけダウンロードします。huggingface.co に接続できない環境では使えません。

## 起動する

1. このディレクトリで依存パッケージを入れます。

   ```bash
   npm install
   ```

2. 開発サーバーを起動し、表示された URL（通常は `http://localhost:5173/`）を開きます。

   ```bash
   npm run dev
   ```

3. **サンプル（日本語）** を押します。最初の解析では、モデルをダウンロードします。進み具合は上部に表示します。同梱の画像にボックスが重なって表示されれば成功です。

4. 翻訳を試すには、**サンプル（英語）** を押し、解析が終わってから **日本語に翻訳** を押します。最初の翻訳では、翻訳モデルをダウンロードします。右のパネルの英文の下に日本語の訳文が表示されれば成功です。

## モデルの保存

モデルは、最初に使うときにブラウザが Hugging Face から直接ダウンロードして保存します。保存済みのモデルは、通信せずに読み込みます。

- **レイアウト認識** のチェックを外している間は、レイアウト認識のモデル（約 130 MB）をダウンロードしません。チェックを入れて最初に解析するときにダウンロードします。
- 翻訳モデル（約 570 MB）は、**日本語に翻訳** を最初に押したときにダウンロードします。翻訳を使わなければダウンロードしません。
- WebGPU と WASM は同じモデルを使います。切り替えてもダウンロードし直しません。
- レイアウト認識と OCR のモデルのダウンロードに失敗すると、上部に「解析に失敗しました」と理由を表示します。同じ画像をもう一度投入してください。保存が済んだモデルは飛ばし、失敗したモデルを最初から取り直します。
- 翻訳モデルのダウンロードに失敗すると、上部に「翻訳に失敗しました」と理由を表示します。もう一度 **日本語に翻訳** を押してください。
- 保存先は、開いた URL（`http://localhost:5173/` など）ごとに分かれます。ポートやブラウザを変えた場合と、シークレットウィンドウでは、ダウンロードし直します。
- 保存したモデルを消すには、ブラウザの設定で、開いた URL のサイトデータ（Cookie と同じ分類）を削除します。「キャッシュされた画像とファイル」の削除では消えません。

## 使う

- 画像をページにドラッグ＆ドロップします。**画像を選ぶ** からの選択と、クリップボードからの貼り付けも使えます。受け付けるのは、ブラウザが表示できる画像 1 枚です。PDF は読めません。
- 画像上のボックスにマウスを乗せると、領域の種類、スコア、文字を表示します。ボックスの番号は読み順です。
- 波線の付いた文字は、認識の確信度が 80% 未満の文字です。ボックスのツールチップに、その文字と次の候補を確信度つきで表示します。右のパネルでは、波線の文字にマウスを乗せると候補が出ます。JSON には全文字の確信度と候補が入ります。
- 右のパネルは、全領域の文字を読み順に並べます。ボックスかパネルの項目をクリックすると、その文字をコピーします。**全文コピー** は、表示中の全領域の文字をコピーします。
- **WebGPU** と **WASM** を切り替えると、同じ画像を解析し直します。対応ブラウザでは WebGPU が初期選択です。処理時間は上部に表示します。
- **レイアウト認識** のチェックを外すと、レイアウト認識を省いて OCR だけを実行し、文字の行ごとにボックスを表示します。行の番号は上から順で、段組みは考慮しません。
- 解析中は、画像の投入と切り替えを受け付けません。完了を待ってください。
- スコアは、領域検出の確信度（0〜1）です。**スコア** のスライダーの初期値は 0.5 で、それ未満の領域は表示しません。検出されるはずの領域が出ないときは、スライダーを下げてください。
- 解析後に上部に並ぶボタンは、領域の種類ごとに表示を切り替えます。スライダーもボタンも、解析はやり直しません。
- **JSON** は、領域、文字、処理時間を `ocr-result.json` としてダウンロードします。翻訳した領域には、訳文が `translation` として入ります。
- **サンプル（英語）** は、同梱の英語の文書画像を解析します。
- **日本語に翻訳** は、右のパネルに並んでいる項目を順に日本語へ翻訳し、原文の下に訳文を表示します。破線のボックスの行も翻訳します。翻訳もブラウザの中だけで実行します。進み具合は上部に表示します。このボタンは、解析が終わるまで押せません。
- スライダーやボタンで隠している領域は翻訳しません。翻訳のあとで表示した領域には訳文がありません。もう一度 **日本語に翻訳** を押すと、訳文のない項目だけを翻訳します。
- 画像を投入するか、解析し直すと、訳文をすべて消します。翻訳の途中なら翻訳も中止します。WebGPU と WASM の切り替えと、**レイアウト認識** のチェックの変更も、解析のやり直しです。もう一度 **日本語に翻訳** を押してください。
- 翻訳に失敗すると、上部に「翻訳に失敗しました」と理由を表示します。もう一度 **日本語に翻訳** を押すと、訳文のない項目だけを翻訳します。
- 破線のボックスは、どの領域にも入らなかった文字の行です。番号はなく、絞り込みの対象にもなりません。

WebGPU での解析に失敗した場合は、自動で WASM に切り替えて解析し、理由を上部に表示します。

## 既知の制限

- 表は、文字の位置から行と列を推定して格子で表示します。コピーするとタブ区切りになります。結合セル、セル内の改行、1 行だけの表は正しく扱えません。
- 数式と印章は構造を解析しません。通常の文字として読みます。
- 傾いた文字の行は精度が落ちます。
- 縦書きは、縦長の行を 90° 回して読むだけです。精度は確認していません。
- 文書の向きと歪みは補正しません。
- 表の領域は翻訳しません。
- 翻訳は領域ごとに独立しています。前後の領域の文脈は使いません。
- 訳文はコピーできません。**全文コピー** も、項目のクリックも、原文だけをコピーします。訳文を取り出すには **JSON** を使ってください。
- 翻訳先は日本語だけです。翻訳元の言語は指定せず、モデルが判断します。動作を確認したのは英語の文字だけです。
- 翻訳は、WebGPU と WASM の切り替えに関係なく、ブラウザが WebGPU に対応していれば WebGPU を使います。対応していないブラウザでは CPU で実行するので、遅くなります。
- 長辺が 960 px を超える画像は、文字検出の前に 960 px へ縮小します。小さい文字は検出できないことがあります。

## 開発

ビルド、テスト、検査、整形には [Vite+](https://viteplus.dev/guide/) を使います。プロジェクト内の `vite-plus` だけで動くので、`vp` コマンドを別に入れる必要はありません。

整形、検査、型検査をまとめて実行します。

```bash
npm run check
```

単体テストを実行します。

```bash
npm test
```

コードを整形します。

```bash
npm run format
```

## 公開する

`npm run build` が作る `dist/` は、静的なファイルだけです。どの静的ホスティングの、どのディレクトリにも置けます。

`main` に push すると、CI が検査のあとに `dist/` を GitHub Pages へデプロイします。先に、リポジトリの **Settings** → **Pages** で **Source** を **GitHub Actions** にしてください。設定していないと、`deploy` ジョブが失敗します。

WASM のマルチスレッドには、`Cross-Origin-Opener-Policy` と `Cross-Origin-Embedder-Policy` の応答ヘッダーが必要です。GitHub Pages のようにヘッダーを設定できないホスティングでは、Service Worker（`public/coi-sw.js`）が代わりに付けます。このため、最初に開いたときにページが 1 回だけ自動で再読み込みされます。
